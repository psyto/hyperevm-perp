VERDICT: CHANGES

1. **High — the spec does not measure the production contract’s flatten path.** `liquidate()` only removes EVM exposure; a later `hedge()` reads `coreLots()` and sends a non-reduce-only IOC. The proposed `rawIocReduceOnly` is test-only and manually sized/directed. Results must be framed as CoreWriter primitive measurements, or an eventual `liquidate → hedge` integration path must be measured separately. [HedgedPerp.sol](src/HedgedPerp.sol:218)

2. **High — the read-lag design cannot support its stated claims yet.** It claims to measure `0x800`, `0x80F`, `0x807`, and `0x80E`, but specifies no measurement for oracle or BBO. The recorder currently records order/status timestamps, not a demonstrated fill timestamp source. For `0x800`, pin every read to an explicit block number/hash and backfill skipped blocks; otherwise “every new block” using `latest` can miss the first visible block. The result is an observation interval, not an exact delay, because EVM block timestamps are whole seconds. Likewise, an `eth_call` at `latest` and a later `clearinghouseState` response are not a common snapshot: report paired divergence with request/response bounds and ordering, not inferred precompile staleness.

3. **High — recovery remains capable of opening exposure unless it is converted to reduce-only.** Current `unwind()` calls non-reduce-only `rawIoc`; Core can liquidate/ADL/change the position after the preflight read but before the delayed CoreWriter action, allowing that recovery order to increase or flip exposure. Step 5 must use `rawIocReduceOnly` for every close and recovery close, require the exact pending cloid plus a strict terminal `orderStatus` payload before acknowledgement, and leave the slot locked on timeout or any mismatch. [orders.py](recorder/orders.py:235)

4. **Medium — the four close kinds are useful but incomplete for a liquidation path.** `flat` and `over` are correctly worded as confirmations, not assumptions. Add both long and short cases, partial/partial-cancel behavior and residual-close handling, and a close whose position changes independently before CoreWriter execution. The latter is specifically relevant because prior reviews identify Core liquidation/ADL as invalidating position-derived assumptions. A tight zero-fill IOC does not cover partial execution.

5. **Medium — sample sizes and book methodology overstate what can be concluded.** With zero failures, 30, 10, and 5 trials still leave approximate one-sided 95% failure-rate bounds of 9.5%, 25.9%, and 45.1%, respectively; `p90` from five or ten observations is effectively an extreme order statistic. Spread samples across times/days, randomize kinds/sides, and report confidence bounds and all exclusions. For mainnet books, define buy and sell impact, baseline, fees, VWAP/depth-walk rules, and “insufficient displayed depth”; label results as instantaneous displayed-book estimates, not executable close cost. Record response timing, market identity, missed intervals, and raw snapshots.
